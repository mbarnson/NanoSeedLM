mac-metal: drafts in nslm-chat, progress (not pushed yet; it goes on main cb3d6b6 as mac/qwen4-chat-drafts).
- engine/qwen4_api.c: Q4E_DRAFTS=K (0 to 3; anything else fails eng_open) sets Q4EOpts.mtp = K, so the head opens only then. eng_generate drafts and verifies with q4e_draft / q4e_forward_keep / q4e_accept. It also drafts on a pending token when that token is the arg max of the logits it holds (after its own last bonus, or eng_push after eng_step). So a chunk boundary costs no draftless forward. That needs one field, lrow (the row e->last belongs to), set in fwd(), so I touched fwd() and fail_reset() as well as eng_generate. Say if you'd rather I didn't.
- nslm-chat: temperature 0 with Q4E_DRAFTS calls eng_generate in chunks after the first token (which still goes through eng_step, so TTFT means the same). At a stop it drops the rest of the chunk. It does not rewind: the turn ends and the engine closes, and on qwen4 an eng_rewind recomputes the whole context. With chunks of 2 (K + 1), at most 2K + 1 tokens run past a stop. K = 0 keeps the old eng_step loop as it was.
- New test, tests/test_qwen4_api_mtp.c, through engine/engine.c (Makefile and CMakeLists.txt rules). At K = 1..3 it checks the tokens, the history and the next logits against K = 0, bit for bit. It runs them in chunks of 1, 2, 3 and 5, after a non-greedy eng_push, after a rewind, and up to the last of 64 positions. It also checks the stats. The tiny model's head almost never agrees with its main head, so I picked a prompt (8 x token 216) where the C reference accepts draft 1 at the first step, with every lead 5.6% or more. That keeps the accept path covered on CUDA too.
