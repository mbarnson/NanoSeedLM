# Trellis experts on the RTX 4080: decode and prompt against P3 (2026-11-05)

**Result.** Take trellis-coded experts with K = 4 for `down_proj` and K = 3 for the rest. With the automatic expert
cache, they decode 27% faster than P3 seeds and read prompts 22% faster. Their KL against BF16 is about P3's (0.0619
against 0.0600), and they are 8 GB smaller. Trellis K = 3 is 43% and 61% faster, at a KL of 0.0765. Trellis K = 4 is
8% slower: its experts are 3% larger than P3's, so the cache holds fewer of them. Decode here is bound by the PCIe
copies of missed experts, so the size of an expert sets the speed.

**Status.** Current. Gate TC of the [trellis plan](../plans/2026-11-05-trellis-experts.md) (step T3) passes for the mix
and for K = 3.

## Setup

- Machine: pc-cuda's Windows 11 PC, RTX 4080 (16 GB, PCIe 4), CUDA 13.1, clang-cl Release build of `54a7130` (no CUDA
  change since). The PC ran nothing else. P3 and the mix and K = 3 ran 03:24 to 03:35 UTC, K = 4 01:01 to 01:14 UTC.
- Packs: the P3 folder, whole, with each pack's `.blkt` banks beside its shards (hard links). The engine puts each bank
  in place of the P3 expert tensor of the same name. Banks from [the KL pages](2026-11-05-trellis-mixes.md), L = 12.
  - Mix: `gate_proj` and `up_proj` from K = 3, `down_proj` from K = 4.
- Decode: `nslm-qwen4-gen`, the code prompt, 256 tokens at most, the automatic expert cache, two rounds for each pack.
- Prompt: 2,994 tokens of wikitext-2 with `--raw`, one run for each pack.
- KL: llama.cpp against BF16, from [Trellis packs and Unsloth's curve](2026-11-05-trellis-mixes.md).

Each pack wrote the same text in both rounds. A P3 prompt run at 01:01 UTC gave 599.3 tokens per second.

## Notes

- The cache's slots follow the size of an expert: 16% more for the mix and 28% more for K = 3. More slots give fewer
  misses, and each miss copies fewer bytes over PCIe. With the weights in VRAM, the trellis kernels are 1.5 to 1.7
  times as fast as P3's (the kernel benches). So nothing works against the smaller packs.
- K = 4 has the best KL (0.0398) but is 8% slower than P3. On a GPU that holds all experts, its speed is not bound by
  PCIe. That case is not measured here.
- Prompt rows gain too, because the prompt passes copy the missed experts in the same way.
- The KL pages emulate the trellis experts in llama.cpp. These runs use the engine's own trellis kernels (`tq_experts`
  and the grouped GEMM). The engine's test checks them against the C reference on a tiny model.
- One text, one machine. The M4 Max runs are on their own page when they finish.
