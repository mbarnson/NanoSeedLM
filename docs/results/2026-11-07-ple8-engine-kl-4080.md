# The 8-bit PLE table in the CUDA engine, on the RTX 4080 (2026-11-07)

**Result.** In the CUDA engine, TCQ3 with its own 8-bit PLE table is 35% closer to a run with Unsloth's Q8_0 table than
TCQ3 with v0.1.0's 4-bit table: a KL of 0.0314 against 0.0481. Top-1 agreement is 95.7% against 93.7%. The control, the
reference run against itself, gives exactly 0, so the engine is deterministic and reads the table soundly. The plan's
bar of 0.002 was wrong: any two tables that are not the same bits flip a few expert routes, and those tokens carry the
mean (median 0.0008, 99th percentile 0.46).

**Status.** Current. Gate PC of [plan ple-8bit](../plans/2026-11-07-ple-8bit.md). A reference with Qwen's BF16 table
would show which of the two 8-bit tables is closer to BF16. It is not measured yet.

## Setup

- pc-cuda: RTX 4080 (16 GB), Windows, `nslm-qwen4-kld` from 8bfed94's cl build (the engine code of a8a3416).
- TCQ3 at the job's commit `df54b30e` (the same tensors as main `a850ead9`), and TCQ3 as in v0.1.0 for the scale run.
- The reference: v0.1.0's TCQ3 with `--ref-ple-gguf` set to Unsloth's Q8_0 table
  (`engram/Qwen3.8-Flash-Next-engram-Q8_0.gguf_file`). `--expert-cache-gb -1`.
- Text: the first 1,024 tokens of wikitext-2's `wiki.test.raw`.

## Results

| Model against the reference | Mean KL | Median KL | 99th percentile | Top-1 | Perplexity |
|---|---|---|---|---|---|
| TCQ3, the pack's 8-bit table | 0.0314 | 0.00082 | 0.459 | 95.70% | 2.039 |
| TCQ3 as in v0.1.0, its 4-bit table | 0.0481 | 0.00127 | 0.550 | 93.65% | 2.084 |
| The reference against itself | 0 | 0 | 0 | 100% | 2.024 |

## Notes

- The tables differ by about 4e-5 RMS. Unsloth's Q8_0 is 4.07e-5 from BF16, and the 8-bit table 3.58e-5
  ([the encoding page](2026-11-07-ple8-encoding.md)). So neither run is the BF16 truth, and this KL measures the
  distance between two near tables, not the error of either.
- On the M4 Max, nslm-chat with the 8-bit table gave the same text as with the Q8_0 table on the merge prompt
  (`37b66ffc`, gate PB).
